Async SQLAlchemy ORM Layer

An async SQLAlchemy ORM layer: a session per request, relationship loading without N+1, transactions and repositories you can test.

medium2–4 daysVerified 2026-08-19
PostgreSQLPython
Read it on GitHub ↗ Back to the catalogue

Declarative models, a session scoped to one request, repositories that return objects rather than rows — and relationship loading made explicit, because in async SQLAlchemy the convenient default does not fail slowly, it raises.

Complexity: medium · Typical build: 2–4 days · Verified: 2026-08-19 (re-check after ~90 days)

Examples in: Python, with SQLAlchemy 2.0 and asyncpg. The architecture is language-agnostic: sections 5, 10 and 11 hold wherever you build this. Section 4 is illustrative — if your project is in another language, your agent translates the idioms rather than importing them, and nothing is lost. The equivalents are Drizzle or Prisma in TypeScript, Ecto.Repo with preload in Elixir, and ActiveRecord with includes in Rails — where the N+1 problem is identical and only the error is quieter.

Use when: the data model has relationships worth traversing, several places need the same queries, and you want transaction boundaries in one place rather than repeated at every call site.

Not for: a service whose data access is a handful of hand-written analytical queries. An ORM adds an object graph, a session lifecycle and a loading strategy to a problem that had none, and for reporting workloads the SQL was the clearer artefact all along. Mixing is fine — the ORM for the write model, plain SQL for the reports.

1. Why the convenient default is not available here

In synchronous SQLAlchemy, touching order.customer on an object whose customer was not loaded issues a query and returns the answer. It is the feature that makes the ORM pleasant, and it is the feature that produces N+1: a list endpoint over a hundred orders quietly runs a hundred and one queries, and nothing in the response says so.

Async SQLAlchemy cannot do this at all, and the reason is worth understanding rather than working around. Attribute access goes through a property, properties cannot be async, and the ORM's internals are synchronous code driven through a greenlet that yields to the event loop when it needs IO. Reached from outside that greenlet, the machinery has no way to await. It raises MissingGreenlet.

Sync ORM, lazy by default Async ORM, loading declared
N+1 is a performance bug found weeks later on a dashboard Unloaded access raises immediately, in the first test that touches it
The query count depends on what the template happened to render The query count is a property of the query, visible where it is written
commit() expires attributes and they transparently reload commit() expires attributes and the next read raises

The third row is where teams lose an afternoon. expire_on_commit defaults to true, so after a commit every attribute is expired — including plain columns that were already loaded. Reading order.id after committing raises, and the traceback points at an attribute access rather than at the commit that caused it.

This is a better situation than the sync default, not a worse one. The failure is loud, immediate, and in the test rather than in production. The work is to stop fighting it and declare loading on purpose.

The rule the diagram encodes: the transaction boundary is the dependency, not the repository. A repository that commits cannot be composed — two of them in one request produce two transactions, and the second failing leaves the first already written.

app/

│   ├── session.py      the async engine, the session factory, the dependency
│   └── naming.py       the constraint naming convention
├── models/
│   ├── order.py
│   └── product.py
└── repositories/
    ├── base.py         generic CRUD over one model
    └── orders.py       the queries that are actually about orders

One rule: a repository never commits. It reads, it adds, it flushes when it needs a generated id — and the transaction ends where the request ends. Break it and every repository becomes its own transaction, so a request that touches two of them can no longer roll back as a unit, and there is no error to tell you.

4. Reference implementation

# app/db/base.py
from datetime import datetime
from sqlalchemy import MetaData, func
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column

# Every constraint gets a deterministic name. Without this, Postgres invents names,
# and Alembic's autogenerate cannot detect changes to constraints it cannot name —
# so a migration silently omits them. Set this before the first table exists;
# afterwards it is a rename migration for every constraint in the database.
NAMING = {
    "ix": "ix_%(column_0_label)s",
    "uq": "uq_%(table_name)s_%(column_0_name)s",
    "ck": "ck_%(table_name)s_%(constraint_name)s",
    "fk": "fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s",
    "pk": "pk_%(table_name)s",
}


class Base(DeclarativeBase):
    metadata = MetaData(naming_convention=NAMING)


class TimestampMixin:
    created_at: Mapped[datetime] = mapped_column(server_default=func.now())
    # server_default, not default: a Python default is wrong for rows written by a
    # migration, a bulk load or psql, and those rows are exactly the ones you later
    # cannot explain.
    updated_at: Mapped[datetime] = mapped_column(
        server_default=func.now(), onupdate=func.now()
    )

# app/models/order.py
from decimal import Decimal
from sqlalchemy import ForeignKey, Numeric
from sqlalchemy.orm import Mapped, mapped_column, relationship
from app.db.base import Base, TimestampMixin


class Order(Base, TimestampMixin):
    __tablename__ = "orders"

    id: Mapped[int] = mapped_column(primary_key=True)
    customer_id: Mapped[int] = mapped_column(ForeignKey("customers.id"), index=True)
    total: Mapped[Decimal] = mapped_column(Numeric(12, 2))
    # Numeric, never Float. Float loses cents at the edges and nothing raises.

    # lazy="raise" is the load-bearing line in this file. It converts an
    # unintended lazy load from a silent extra query into an exception at the
    # access — which means the first test that walks the relationship fails, rather
    # than a dashboard six weeks later showing 101 queries on a list endpoint.
    items: Mapped[list["OrderItem"]] = relationship(
        back_populates="order", lazy="raise", cascade="all, delete-orphan"
    )
    customer: Mapped["Customer"] = relationship(back_populates="orders", lazy="raise")

# app/db/session.py
from collections.abc import AsyncIterator
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine
from app.config import get_settings

settings = get_settings()

engine = create_async_engine(
    str(settings.database_url),
    pool_size=10,
    max_overflow=0,          # a hard ceiling; overflow hides the fact that you are over budget
    pool_pre_ping=True,      # one cheap round trip beats the first query of every
                             # request after a database restart failing
    pool_recycle=1800,       # below any proxy or firewall idle timeout, so the pool
                             # never hands out a socket the network has already dropped
)

SessionFactory = async_sessionmaker(
    engine,
    expire_on_commit=False,  # otherwise every attribute is expired after commit and the
                             # next read — even of a plain column — raises MissingGreenlet
    autoflush=False,         # implicit flushes mid-query reorder writes in ways that are
                             # very hard to reason about; flush deliberately instead
)


async def get_session() -> AsyncIterator[AsyncSession]:
    # The transaction boundary. One request, one transaction: commit if the handler
    # returned, roll back if it raised, close either way.
    async with SessionFactory() as session:
        try:
            yield session
            await session.commit()
        except Exception:
            await session.rollback()
            raise

# app/repositories/orders.py
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy.orm import joinedload, selectinload
from app.models.order import Order


class OrderRepository:
    def __init__(self, session: AsyncSession) -> None:
        self.session = session          # given, never created — so a test can hand it
                                        # a session inside a transaction it will roll back

    async def list_with_items(self, limit: int) -> list[Order]:
        stmt = (
            select(Order)
            .options(
                # selectinload for a collection: a second query with WHERE id IN (...).
                # joinedload here would multiply the parent row by its children and
                # make LIMIT count item rows instead of orders.
                selectinload(Order.items),
                # joinedload for the many-to-one: one row per order, one query total.
                joinedload(Order.customer),
            )
            .order_by(Order.id.desc())
            .limit(limit)
        )
        return list((await self.session.execute(stmt)).scalars().all())

    async def add(self, order: Order) -> Order:
        self.session.add(order)
        # flush, never commit: this sends the INSERT and populates the generated id
        # while leaving the transaction open for whatever else this request does.
        await self.session.flush()
        return order

5. Golden-standard rules

Rule Why
Forbidden: a repository or service calling commit() The transaction must span the request. A repository that commits cannot be composed, and a second failure leaves the first write already permanent.
Forbidden: lazy left at its default on any relationship The default is a silent extra query per object in sync and an exception in async. Declaring lazy="raise" makes the loading strategy a decision instead of an accident.
Forbidden: Float for money Binary floating point cannot represent cents exactly, the drift is small, and nothing raises. Use the database's exact numeric type.
Forbidden: SQLAlchemy pooling on top of a pooler in transaction mode Two poolers each believe they own the connection lifecycle. Use a null pool and let the external one do its job.
expire_on_commit=False The default expires every attribute after commit, so reading a plain column afterwards raises, with a traceback pointing at the read rather than the commit.
Loading strategy is chosen per query, not per model The right strategy for a detail endpoint is wrong for a list endpoint. lazy="raise" on the model forces the choice to be made where the query is.
selectinload for collections, joinedload for many-to-one A join to a collection multiplies parent rows by children, which silently breaks LIMIT and inflates the transferred result.
A repository receives a session; it never opens one It is what lets the same code run in a request, in a background job, and in a test that rolls back — with no branch for each.
Every constraint has an explicit naming convention, set before the first table Autogenerate cannot detect changes to a constraint it cannot name. Adding this later is a rename migration for every constraint you have.
Timestamps use server defaults A Python default is absent for rows written by a migration, a bulk load or a human at psql — and those are the rows whose history you will later need.
pool_recycle is below the shortest idle timeout on the path Otherwise the pool eventually hands out a socket that a proxy or firewall has already dropped, and the failure lands on a user's request.
Flush deliberately; do not rely on autoflush Implicit flushes fire mid-query and reorder writes in ways that are very hard to reconstruct from a log.

6. Data contracts

class Order(Base):
    id: Mapped[int] = mapped_column(primary_key=True)
    total: Mapped[Decimal] = mapped_column(Numeric(12, 2))
    # not float — cents do not survive binary floating point
    customer_id: Mapped[int] = mapped_column(ForeignKey("customers.id"), index=True)
    # the index is not optional: an unindexed foreign key makes every join and
    # every cascade delete a sequential scan, and it stays fast until the table
    # is large enough that it is expensive to fix
    items: Mapped[list["OrderItem"]] = relationship(lazy="raise")
    # the annotation is the contract: a collection, never None, and never loaded
    # by accident

Mapped[X] versus Mapped[X | None] is the nullability of the column, not a convenience. Getting it wrong means the model claims a value is always present while the table permits null, and the first null row raises inside serialisation — far from the migration that allowed it.

7. Build order

  1. Base, naming convention, one model, one table. The naming convention has to exist before the first table; retrofitting it renames every constraint.
  2. Session factory and the dependency, with expire_on_commit=False. Prove one request equals one transaction: raise inside a handler after a write and assert nothing was persisted.
  3. One repository, taking a session, with a test that passes it a session inside a transaction the test rolls back.
  4. Relationships, all with lazy="raise". Add a test that walks a relationship without loading it and expects the exception — this is the guard, so it needs a test of its own.
  5. Explicit loading on the list query, with a query-count assertion. Two queries for a list of a hundred orders with items, not a hundred and one.
  6. Pool settings — pre-ping, recycle, and the null pool if a pooler is in front.
  7. Concurrency check: run the list endpoint under parallel load and confirm the pool does not exhaust and no session is shared across tasks.

Step 4 before step 5 because lazy="raise" is what makes step 5's mistakes visible. In the other order, a missing loader is just a slow endpoint.

10. Failure modes

Symptom Cause Fix
MissingGreenlet on a line that only reads an attribute The attribute was expired by a commit, or the relationship was never loaded — either way the ORM would need to emit IO from a property, which it cannot expire_on_commit=False, and load relationships explicitly in the query
A list endpoint is fast with ten rows and unusable with a thousand N+1: one query for the list, one per row for a relationship Add selectinload or joinedload, and assert the query count in a test
A list endpoint with LIMIT 20 returns fewer than twenty parents joinedload on a collection multiplied parent rows by children, and the limit applied to the joined rows selectinload for collections
A request writes half its changes and returns success Something committed mid-request, so the later failure rolled back only what came after Remove every commit outside the session dependency
Rows appear that no code path explains, or writes land in an unexpected order Autoflush fired inside an unrelated query autoflush=False and flush where you mean to
The first request after a database restart always fails The pool handed out a connection that was severed while idle pool_pre_ping=True, and pool_recycle below the shortest idle timeout on the path
Connections exhaust under moderate load, and the count exceeds what the pool was configured for max_overflow is silently adding connections beyond pool_size Set max_overflow=0 so the ceiling is the ceiling
A cascade delete of one row takes minutes The foreign key has no index, so each cascade step is a sequential scan Index every foreign key
Money is off by a cent on large orders A relationship or column used Float Numeric with an explicit scale
Two concurrent requests interfere with each other's data A session was stored on a module or shared between tasks — a session is not concurrency-safe One session per request, obtained from the dependency
Alembic generates a migration that silently omits a constraint change The constraint has a database-generated name, which autogenerate cannot compare Set the naming convention on the metadata before the first table

11. Definition of done

  • Every relationship declares an explicit lazy strategy; a test walks the models' mappers and fails on any that does not
  • A test accesses an unloaded relationship and asserts the raise, so the guard itself is covered
  • expire_on_commit=False on the session factory, with a test reading a column after commit
  • A list endpoint's query count is asserted and is constant in the number of rows returned
  • Raising inside a handler after a write leaves nothing persisted, covered by a test
  • grep finds no commit() outside the session dependency, checked in CI
  • Every repository takes a session as a constructor argument and a test passes one inside a rolled-back transaction
  • The metadata naming convention is set and every existing constraint matches it, verified against the live schema
  • Every foreign key column has an index, verified by a query against the catalogue rather than by reading the models
  • No monetary or exact-decimal column is mapped to Float, verified by inspecting column types
  • pool_recycle is set below the shortest idle timeout on the network path, with that timeout named in a comment
  • Running the test suite in parallel produces the same results as running it serially
